# AI client guide

Mega Kadence Bridge is model-agnostic. The WordPress plugin exposes an HTTP
API; it does not invoke a model, require a model API key, or depend on a
particular coding-agent CLI. Every client uses the same three values:

```dotenv
BRIDGE_URL=https://example.com/wp-json/mega-kadence-bridge/v1
BRIDGE_USER=mkb-agent
BRIDGE_PASS=xxxx xxxx xxxx xxxx xxxx xxxx
```

`BRIDGE_USER` is generated by the installed plugin and must be read from the
Settings page or credentials file. New installs use `mkb-agent`. Upgraded sites
may correctly retain the historical `claude-bot` login.

Keep `.env` outside version control. Parse it as data instead of sourcing it,
and pass Basic Authentication through the client's secret-aware HTTP mechanism.
Never copy the password into an AI prompt, transcript, issue, report, fixture,
or committed file.

## Universal first call

Every client starts with authenticated `GET ${BRIDGE_URL}/capabilities`. The
response identifies the site and locked domain, installed Kadence and commerce
stack, available endpoint groups, and the operating doctrine. Do not hard-code
assumptions that the response can answer.

## Codex

Open the project containing this repository and its private `.env`, then ask
Codex to use `$mega-kadence-bridge` for the authorized site. Codex should follow
the root `SKILL.md`, discover capabilities first, keep credentials out of
output, and use the same read-write-verify-rollback loop as any other client.

Example request:

> Use $mega-kadence-bridge on the authorized site in this project's .env.
> Inspect capabilities and the current palette, then change the primary color
> to forest green. Preserve the other palette slots, flush caches, and verify
> the rendered home page. Do not make any other changes.

## Claude, Cursor, and other agents

Give the client access to this repository (or copy the `SKILL.md` and this
guide into its supported instruction format), plus the local `.env`. The REST
contract is identical. Provider-specific login is only for the agent itself;
it is not part of MKB authentication.

## Plain HTTP clients

Any client capable of WordPress Application Password Basic Authentication and
JSON can use MKB. A safe integration should:

1. Read secrets from a secret store or local untracked file.
2. Call `/capabilities` and verify `bridge.domain_match` is not `false`.
3. Read current state before mutation.
4. Send the narrowest change and retain its snapshot ID.
5. Read state back, flush caches when needed, and verify `/render` output.
6. Roll back the captured snapshot if verification fails.

## Compatibility boundary

The bridge is the transport and Kadence capability layer. Model selection,
provider login, prompting, orchestration, and billing remain the responsibility
of the calling agent or workflow. MKB never needs OpenAI, Anthropic, Google, or
another model-provider credential.
